# FlashAttention V3：Block 级复用 + 严格顺序版

## 1. 设计目标

V2 已经把所有测试跑通，并暴露出两个可继续优化的点：

1. 每个 query 行都重复从全局读取 K/V；
2. 概率求和使用 warp 树形归约，和参考实现的串行求和仍有末位差异。

V3 的目标是：

- 一个 block 处理 4 个 query 行，Q/K/V/P 全部放共享内存；
- K/V tile 被 block 内 4 个 warp 共同复用；
- 概率 `exp` 由 32 个 lane 并行计算；
- 分母仍由 `lane 0` 按 key 顺序串行累加，保持参考实现的求和顺序；
- 继续通过全部 28 项测试。

## 2. 数据布局与 causal 语义

```text
Q: [B, T, Hq, D]
K: [B, S, Hkv, D]
V: [B, S, Hkv, D]
O: [B, T, Hq, D]

group_size = Hq / Hkv
hkv        = hq / group_size
q_idx      = blockIdx.x * BQ + warp
```

causal 采用左上角对齐：

```text
row_key_end = min(S, q_idx + 1)
block_key_end = min(S, blockIdx.x * BQ + BQ)
```

block 的最后一个 query 行决定了 K/V tile 的上界，后续 tile 直接跳过，避免无效计算。

## 3. 实现结构

- Grid：`(ceil(T/4), Hq, B)`；
- Block：4 个 warp，共 128 线程；
- 共享内存布局：

```text
q_s       : 4 × D
k_s       : BK × (D + 1)
v_s       : BK × (D + 1)
p_val_s   : 4 × BK
p_scale_s : 4 × BK
```

- 全行 max 预扫描：每个 lane 负责不同 key，顺序做 `D` 维点积，warp shuffle 求最大值；
- 主循环按 `BK=32` 装载 K/V；
- 概率阶段：

```cpp
for (int jj = lane; jj < count; jj += 32) {
  float dot = 0;
  for (int d = 0; d < head_dim; ++d)
    dot = fmaf(q_s[warp * D + d], k_s[jj * stride + d], dot);

  float exp_scale;
  const float exp_value = expf_parts(dot * scale - row_max, exp_scale);
  p_val_s[warp * BK + jj] = exp_value;
  p_scale_s[warp * BK + jj] = exp_scale;
}
```

- 分母阶段：`lane 0` 按 `jj = 0, 1, 2, ...` 串行执行：

```cpp
row_sum = __fmaf_rn(p_val_s[jj], p_scale_s[jj], row_sum);
```

- PV 阶段：每个 lane 绑定输出维度 `d`，按 key 顺序累加：

```cpp
out0 = fmaf(p, v_s[jj * stride + lane], out0);
```

- 最后统一乘 `1 / row_sum` 写回。

`expf_parts()` 使用 `ex2.approx.ftz` 加高低位拆分，和参考实现的数值路径一致；这是 float 误差能压到 `5e-6` 以下的关键。

## 4. 修改前 / 修改后

**修改前：lane 0 串行计算概率**

```cpp
if (count > 0 && lane == 0) {
  for (int jj = 0; jj < count; ++jj) {
    float dot = 0;
    for (int d = 0; d < head_dim; ++d)
      dot = fmaf(q_s[warp * D + d], k_s[jj * stride + d], dot);
    float exp_scale;
    const float exp_value = expf_parts(dot * scale - row_max, exp_scale);
    p_s[warp * BK + jj] = exp_value * exp_scale;
    row_sum = __fmaf_rn(exp_value, exp_scale, row_sum);
  }
}
```

问题：32 个 key 的点积和 `exp` 全部压在一个 lane 上，其他 31 个 lane 在 `__syncwarp()` 前空等。旧版虽然 28/28 通过，但最大形状 float 要 **68.81 ms**，half 要 **54.77 ms**。

**修改后：并行算 exp，lane 0 只做有序求和**

```cpp
for (int jj = lane; jj < count; jj += 32) {
  // 每个 lane 算自己的 key，exp 只算一次
  ...
  p_val_s[warp * BK + jj] = exp_value;
  p_scale_s[warp * BK + jj] = exp_scale;
}
__syncwarp();
if (lane == 0) {
  for (int jj = 0; jj < count; ++jj)
    row_sum = __fmaf_rn(p_val_s[warp * BK + jj],
                        p_scale_s[warp * BK + jj], row_sum);
}
```

效果：

- 最大形状 float：`68.81 ms -> 46.59 ms`，提升 **32.3%**；
- 最大形状 half：`54.77 ms -> 26.19 ms`，提升 **52.2%**；
- 28/28 仍然全部通过，float 最大误差 `4.8e-6`。

- V2 的 float 端到端最快；
- V3 的 half 最快，且分母严格按参考顺序求和；
- V3 的 kernel 比 V2 慢约 6.4%，换来了更严格的数值顺序。

## 9. 评价

**优点**

- 28/28 全部通过，float 最大误差 4.8e-6；
- exp 并行后，最大形状 float 提升 32.3%，half 提升 52.2%；
- Q/K/V/P 全部共享，L2 命中 99.53%；
- 分母严格按 key 顺序累加，数值路径最接近 V1/参考实现；
- `Warp Cycles Per Issued Instruction` 为三版最低。

**缺点**

- `lane 0` 串行求和仍是长依赖链，kernel 比 V2 慢约 6%；
- 端到端被三次 H2D 明显拖慢；
- 共享内存/MIO 吞吐接近饱和，继续优化需要考虑更宽的访存或减少共享内存往返。

**结论**：V3 作为默认版本，主打“严格顺序 + 全部通过 + half 最快”；V2 保留为 float 速度优先的备选实现。
