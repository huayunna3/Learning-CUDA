# FlashAttention V2：Warp 并行 + K/V 分块版

## 1. 设计目标

V1 已经证明数值路径正确，但一个 block 只有 0 号线程在算 score，GPU 并行度几乎被浪费。V2 的目标是：

- 一个 warp 负责一个 query 行，block 内 4 个 warp 并行处理 4 行；
- K/V 按 `BK=32` 分块装入共享内存，block 内 4 个 warp 复用同一份 K/V；
- 每个 lane 负责不同的 key，避免 V1 的单线程串行；
- 保持 causal/GQA 语义不变，并继续通过全部 28 项测试。

## 2. 数据布局与下标

沿用 `[B, S, H, D]`：

```text
Q: [B, T, Hq, D]
K: [B, S, Hkv, D]
V: [B, S, Hkv, D]
O: [B, T, Hq, D]
```

```text
group_size = Hq / Hkv
hkv        = hq / group_size
q_idx      = blockIdx.x * 4 + warp
```

causal 下每个 query 行仍只看到 `j <= q_idx`：

```text
row_key_end = min(S, q_idx + 1)
```

## 3. 实现结构

- Grid：`(ceil(T/4), Hq, B)`；
- Block：4 个 warp，共 128 线程；
- 共享内存：
  - `Q`：`4 × D`；
  - `K`：`BK × (D + 1)`；
  - `V`：`BK × (D + 1)`；
  - `P`：`4 × BK`；
- 全行 max 预扫描：每个 lane 处理不同 key，按 `D` 顺序做点积，warp shuffle 求最大值；
- 主循环按 `BK=32` 装载 K/V tile：
  - 每个 lane 负责不同的 key，顺序计算该 key 的 `D` 维点积；
  - 用与参考实现一致的 `expf_parts()` 计算概率；
  - 概率写入共享内存 `p_s`，warp shuffle 求本 tile 的和；
  - 每个 lane 绑定一个输出维度 `d`，按 key 顺序做 `P @ V`；
- 最后统一乘 `1 / row_sum` 写回。

`D + 1` 的 stride 是为了错开共享内存 bank，减少 32 个 lane 同时访问同一 bank 的冲突。

## 4. 关键公式

```text
score[j] = sum_d Q[d] * K[j, d] / sqrt(D)
m        = max_j score[j]
p[j]     = exp(score[j] - m)
l        = sum_j p[j]
O[d]     = (sum_j p[j] * V[j, d]) / l
```

V2 先做整行 max 预扫描，再做概率和 PV。这样 `p[j]` 不会像 online softmax 那样被多次重缩放，float 精度能稳定落在测试容差内。

## 5. 修改前 / 修改后

**修改前：online softmax 版本**

最初 V2 采用逐 tile 更新：

```cpp
const float new_max = fmaxf(row_max, score);
const float alpha = expf(row_max - new_max);
const float p = expf(score - new_max);
row_sum = row_sum * alpha + p;
out0 = out0 * alpha;
out0 += p * v;
```

问题：float 有 **7 项失败**，最大误差约 `1.5e-5`，而容差只有 `1.1e-5 ~ 1.9e-5`。把 double 累加改成 float、把 `expf` 换成 `expf_parts` 都没有消除误差，说明根因是 online 重缩放改变了参考实现的运算顺序。

**修改后：全行 max 预扫描 + lane 并行 key**

```cpp
// 1. 先扫描整行，得到与参考一致的 row_max
for (int j = lane; j < row_key_end; j += 32) {
  float dot = 0;
  for (int d = 0; d < head_dim; ++d)
    dot = fmaf(q_s[warp * head_dim + d], to_float(k[offset + d]), dot);
  local_max = fmaxf(local_max, dot * scale);
}

// 2. 每个 lane 处理不同 key，概率只算一次
for (int jj = lane; jj < count; jj += 32) {
  float dot = 0;
  for (int d = 0; d < head_dim; ++d)
    dot = fmaf(q_s[warp * head_dim + d], k_s[jj * stride + d], dot);
  float p_scale;
  const float p_exp = expf_parts(dot * scale - row_max, p_scale);
  p_s[warp * BK + jj] = p_exp * p_scale;
}
```

修改后的结果：**28 / 28 Passed**。最大 float 误差降到 `5.7e-6`，half 最大误差 `0.0078125`。

这一步的代价是测试平均时间从 online 版的约 `33.6 ms` 升到 `42.3 ms`，但换来了全部通过；相比 V1 仍然快 **3.26 倍**。

## 9. 评价

**优点**

- 28/28 全部通过，float 最大误差 5.7e-6；
- warp 内 31.4 个线程有效，GPU 利用率从 V1 的“单线程”恢复到正常水平；
- K/V 在 block 内共享，L2 命中 99.38%；
- kernel 比 V1 快 9.44 倍，端到端快 3.26 倍。

**缺点**

- 仍然对每个 query 行重复做整行 max 预扫描；
- 共享内存读写压力大，NCU 显示 L1/TEX 已达 93.64%；
- 端到端时间被三次 H2D 明显拖慢；
- 概率求和采用 warp 树形归约，与参考的串行求和仍有末位差异（但已远低于容差）。

**结论**：V2 是当前“速度与正确性平衡最好”的版本；V3 继续从 block 级复用和严格求和顺序入手。
